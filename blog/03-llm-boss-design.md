# 给 Boss 装一个 LLM：延迟、公平性与成本的三角

> 这是「从零实现 Agent」系列的第三篇。项目地址：[mini-agent-harness](https://github.com/jinhan-hu/ai-agent-projects/tree/main/04-agent-harness)

## 一个跑步时冒出来的想法

在《黑神话：悟空》里被某个 Boss 卡了很久之后，我产生了一个想法：

**能不能给 Boss 装一个大模型？**

让它观察玩家的出招习惯，实时见招拆招。难度分级也顺便解决了——低难度用弱一点的模型，高难度用最强的模型。

**这个想法听起来很诱人**：每个玩家遇到的 Boss 都不一样，复玩率暴涨，"智能感"拉满。

**但它有三个硬约束，而且每一个都能用数字算清楚。**

---

## 先泼一盆冷水：自适应 AI 并不新鲜

**"Boss 学习玩家的打法"这件事，游戏业已经做了 20 年。**

| 年份 | 游戏 | 做了什么 |
| ---: | --- | --- |
| 2005 | **F.E.A.R.** | GOAP 行为规划：敌人会包抄、会找掩护、会互相喊话 |
| 2008 | **Left 4 Dead** | ★ **AI Director**：按玩家压力动态调控敌人波次、物资、音乐 |
| 2013 | **Killer Instinct** | Shadow AI 学习你的出招习惯，**复刻你的打法** |
| 2014 | **Alien: Isolation** | 双层 AI：Director（宏观）+ Alien（微观），有"威胁值"机制 |
| 2014 | **Shadow of Mordor** | ★ **Nemesis 系统**：敌人记得你、记仇、会升职 |

**所以"AI 学你的打法"不是 LLM 带来的新东西。**

**真正的问题变成了：LLM 能给这件事带来什么新的？**

---

## LLM 的真正增量：不是"更强"，是"会说话"

| # | 传统 AI | LLM 的增量 |
| ---: | --- | --- |
| 1 | 行为是**预设行为树的组合** | 生成从未出现过的应对（开放式策略） |
| 2 | 只会做动作，不会表达 | ★ **会说话**：能嘲讽、能评价、能"记住"你 |
| 3 | "适应性"是调数值 | 能理解语义（"这玩家一直在用重击，因为他怕近身"） |

**第 2 条才是最有价值的。**

**玩家记住的从来不是"这个 Boss 很聪明"，而是"这个 Boss 说：'你上次也是这么死的'"。**

---

# 硬约束一：延迟差两个数量级

## 数字先摆出来

| 环节 | 时间预算 |
| --- | ---: |
| 游戏一帧（60 fps） | **16 毫秒** |
| LLM 一次推理（本地小模型） | 100–500 毫秒 |
| LLM 一次推理（云端大模型） | 800–2000 毫秒 |

**Boss 要做"见招拆招"，必须在玩家出招后 100 毫秒内反应。LLM 根本来不及。**

**如果强行等，玩家感受到的不是"智能"，是"这游戏卡了"。**

## ★ 权威数据：Anthropic 自己也承认做不了

Anthropic 在 2026 年发布过一项研究，[让多个前沿模型控制真实和仿真的机器人](https://www.anthropic.com/research/claude-plays-robotics)。报告里有一句非常直白的话：

> **"Real-time control would require roughly 83 Hz; current non-reasoning inference runs at ~0.2–0.4 Hz, so closing this gap needs roughly two orders of magnitude latency improvement."**
>
> 实时控制需要约 **83 Hz**，而当前（非推理模式）的推理速度只有 **0.2–0.4 Hz**，弥补这个差距需要大约**两个数量级**的延迟改进。

**83 Hz = 每 12 毫秒一个决策。0.2–0.4 Hz = 每 2.5–5 秒一个决策。**

**差了约 200 倍。**

## ★ 而最讽刺的是：他们不得不把物理暂停

报告里还有一句，比上一条更耐人寻味：

> **"we pause the simulator between LLM calls so real-time latency does not become the limiting factor."**
>
> 我们在每次 LLM 调用之间**暂停仿真器**，以免实时延迟成为限制因素。

**翻译过来就是：为了让模型有机会"思考"，他们把物理世界按了暂停键。**

**而这个特权，游戏里没有。**

**——你不可能在 Boss 面前暂停世界 3 秒钟等它想清楚。**

**换句话说：连"暂停物理"这种作弊条件下，模型直接控制关节依然基本失败。真实游戏里只会更糟。**

---

# 硬约束二：更强 ≠ 更好玩

## 通顺但错误的想法

**"难度分级 = 换不同强度的模型"**——这个想法很顺，但它假设了"AI 越强，游戏越好玩"。

**事实不是这样。**

## 三个理由

| # | 问题 | 说明 |
| ---: | --- | --- |
| **1** | **最优解很无聊** | 强模型会学到"永远保持距离，等你出招"——玩家会崩溃 |
| **2** | **无解** | 真正的"见招拆招"意味着没有破绽，玩家赢不了 |
| **3** | ★ **不公平感** | 玩家一旦发现"它在读我的输入"，第一反应是作弊，不是佩服 |

**先例**：DeepMind 的 AlphaStar 打《星际争霸》，被**强制限制 APM（手速）**——因为无限手速的 AI 对人类不公平。

## ★ 另一个反直觉的数据

**同一个 Anthropic 研究里还有一个发现**：给模型更多"思考预算"（reasoning tokens），结果**在大多数任务上没有帮助，甚至有害**：

> "On the classic control tasks, newer models regressed when given a higher reasoning budget."
>
> 在经典控制任务上，较新的模型在获得更高推理预算时反而退化了。

**他们给的解释是**：简单任务上，过度思考（overengineering）反而干扰了本该敏捷的反应。

**★ 这对游戏设计的启示很直接**：

> **"更强的模型"不等于"更好的对手"。**
> **你需要的不是最强的 AI，是"最有趣的 AI"。**

# 硬约束三：成本

## 算一笔账

**一场 Boss 战 5 分钟，每 3 秒调一次 LLM：**

| 项 | 数值 |
| --- | ---: |
| 调用次数 | 100 次 |
| 每次 token | 约 2000 |
| 总计 | **20 万 token / 场** |
| 单价（API 约 2 元/百万 token） | **约 0.4 元 / 场** |

**看起来不多。但乘上玩家数：**

$$100\text{ 万玩家} \times 10\text{ 场/人} \times 0.4\text{ 元} = \textbf{400 万元}$$

**而且这只是"每 3 秒问一次"——离"见招拆招"差得很远。**

**★ 所以云端大模型只能用在"关键 Boss"上，或者干脆用本地小模型。**

---

# ★ 解法：分层——让 LLM 出意图，让传统 AI 出动作

## 核心结构

```
┌─────────────────────────────────────────┐
│ 高频层（每帧，16 ms）                     │
│ 传统游戏 AI：状态机 / 行为树 / GOAP        │
│ → 保证响应速度 + 动作合法性               │
└─────────────────────────────────────────┘
                  ↑ 只接收「战术意图」
┌─────────────────────────────────────────┐
│ 低频层（每 3–5 秒）                       │
│ LLM：输出策略标签，不输出具体动作          │
└─────────────────────────────────────────┘
```

## LLM 输出的应该是这种东西

```json
{
  "player_habit": "喜欢翻滚后突进",
  "my_intent": "改用延迟攻击引诱他翻滚",
  "taunt": "你只会这一招吗？"
}
```

**然后传统 AI 把 `"延迟攻击"` 翻译成行为树里的具体节点。**

**这样：**
- ✅ 延迟可接受（LLM 每 3–5 秒调一次，不在战斗帧内）
- ✅ 动作合法性由传统 AI 保证（LLM 幻觉也只会输出一个不存在的策略名，被丢弃）
- ✅ 玩家感到"被理解"，而不是"被数值碾压"

## ★ 这个结构和 Agent 的架构一模一样

| Agent 组件 | 游戏里的对应 |
| --- | --- |
| LLM 输出 `tool_calls`（结构化意图） | LLM 输出"战术意图" JSON |
| 执行层校验并执行 | 行为树翻译成具体动作 |
| 工具返回结果 → 回填 | 战斗结果 → 回填给 LLM 做下一轮判断 |

**★ 换句话说：给 Boss 装 LLM，本质上是给它装一个 Agent 的决策层 + 一套受限的执行器。**

**我在 [mini-agent-harness](https://github.com/jinhan-hu/ai-agent-projects/tree/main/04-agent-harness) 里实现的就是这个结构——只是那里执行的是 `calculator`，游戏里执行的是"挥刀"。**

# 那么，真正能落地的是什么

| 场景 | 可行度 | 原因 |
| --- | :---: | --- |
| 实时战斗见招拆招 | ❌ | 延迟、公平性、成本三重不可行 |
| **战前 / 战后对话** | ✅ | 不在战斗中，延迟无所谓 |
| **战术层决策（3–5 秒一次）** | ✅ | 延迟可接受 |
| ★ **动态叙事 + 记仇（Nemesis + LLM）** | ★★ **最值得做** | LLM 生成个性台词，成本低 |
| ★ **赛后教练**（分析你的打法并给建议） | ✅ | 全场几百 token，成本可忽略 |

## 我个人最看好的是第四项

**Nemesis 系统（2014）已经证明"敌人记仇"非常有魅力**——它让每个玩家有自己的敌人。

**但它当年的短板是**：记仇的表达方式受限于预设文本，永远是那几句。

**加上 LLM 之后**：敌人可以生成**针对你这一次死亡方式**的嘲讽。

**这不需要实时性，不需要极高成本，也不需要 AI"变强"。**

**它只需要 AI"会说话"。**

---

# 一句话总结

> **"Boss 学你的打法"不需要 LLM——游戏业做了 20 年。**
>
> **LLM 带来的不是"更强的对手"，是"会说话、记得你、能解释自己战术的对手"。**
>
> **而要实现它，必须做分层：LLM 出意图，传统 AI 出动作。**
>
> **这道题真正的难点不是"AI 够不够聪明"，是"你能不能把 AI 放在对的位置上"。**
